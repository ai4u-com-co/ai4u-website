# ai4u-website

Sitio web corporativo público de Ai4U (www.ai4u.com.co): landing, servicios, agentes, portafolio, orderLoader, sitios web y páginas legales. Es un SPA de marketing, sin backend propio. **Repo público: nada de secretos, infraestructura interna ni datos de clientes en código, docs o commits.**

## Stack
- React 18 + TypeScript (`strict: false`) + Vite 5 (puerto dev 3002) + Material UI 6 + React Router 6 + `react-helmet-async`.
- `@ai4u/design-system` fijado por tag de git (`github:ai4u-com-co/sistemaDiseno#v1.4.0`); tokens propios además en `src/components/shared/ui/tokens/`.
- Tests: Vitest (+ Testing Library) y Playwright (`tests/smoke.spec.ts`). Node 20 en CI.

## Comandos (package.json)
- `npm run dev` (o `start`) · `npm run build` · `npm run preview`
- `npm test` (vitest, modo watch) · `npm run test:e2e` (Playwright)
- Build completo como en producción: `npm run build && node scripts/prerender.mjs && node scripts/seo-postbuild.mjs` (reconstruir antes de cada prerender: reescribe `dist/index.html`)
- `npm run validate-translations` · `npm run optimize-images` · `npm run analyze-images` · `npm run lighthouse` · `npm run validate-whatsapp` · `npm run create-social-image`
- No hay script de lint ni de type-check (existe `eslintConfig` en package.json, sin paquete eslint instalado: por confirmar si corre).

## Estructura
- `src/pages/` páginas lazy (excepto Home, ruta crítica); rutas en `src/utils/constants.ts` (`ROUTES`) y montadas en `src/App.tsx`.
- `src/components/shared/ui/{atoms,molecules,organisms,layouts,tokens}` (atomic design), `src/components/agentes/`, `src/context/` (Theme, Loading, Services, Surface), `src/data/` (contenido estático: servicios, agentes, clientes...), `src/hooks/`, `src/utils/` (seo, analytics, api, logger).
- `public/` (robots, llms.txt, manifest, íconos, imágenes; el sitemap se genera en el build), `scripts/` (imágenes, prerender, Lighthouse), `docs/` y `src/docs/` (guías internas, varias con historial de fases; pueden estar desactualizadas).
- Alias `@` -> `src/`. `experiments/`, `fondo emprender/`, `playwright-report/` y `.superpowers/` no son parte de la app.

## Convenciones y trampas
- Convención de texto (`.cursor/rules/text-conventions.mdc`): sin MAYÚSCULAS sostenidas en UI o código; capitalización normal o camelCase.
- Contenido en español; i18n/traducción descrito en `src/docs/INTERNATIONALIZATION.md` y `docs/TRANSLATION_STATUS.md` (hay widget de Google Translate). Estado real: por confirmar.
- Toda variable `VITE_*` queda embebida en el bundle público: nunca poner ahí secretos. El chat de Make.com se eliminó (era un bot que ya no se usa): el contacto es un botón flotante de WhatsApp (`WhatsAppFloat`, en `Layout`) que abre `wa.me/573024906414` con un mensaje prellenado, y las conversaciones se atienden a mano desde el celular. El `Contact` del píxel lo dispara `MetaPixelTracker` al tocar cualquier enlace `wa.me`.
- **SEO / GEO / AEO:** `src/data/seoPages.json` es la lista única de páginas públicas (ruta, título, descripción, tipo, si va al sitemap). De ahí salen el prerender, el `sitemap.xml`, las validaciones y los datos estructurados (`src/utils/jsonld.ts`, un `@graph` por página). Cada página usa `<SEOHead path="/ruta" />`: título, descripción, canónica, Open Graph, Twitter y JSON-LD salen del registro; la canónica NUNCA sale de `window.location` (en el prerender era `localhost`). `index.html` no lleva metadatos de página (duplicaban los de `SEOHead`). Una ruta pública nueva: agregarla al registro, crear la página con `SEOHead` y la ruta en `App.tsx`.
- El HTML de las rutas públicas se prerenderiza tras el build (`scripts/prerender.mjs`, Playwright; en Vercel usa `@sparticuz/chromium`). Después corre `scripts/seo-postbuild.mjs`: genera `dist/sitemap.xml` y `dist/llms-full.txt` (texto de cada página, para asistentes de IA) y **valida cada página** (una sola canónica correcta, sin localhost, descripción única, JSON-LD válido, un H1, fuentes sin bloquear); si algo falla, el build falla. `public/llms.txt` y `public/robots.txt` (con los rastreadores de IA permitidos de forma explícita) son estáticos. `public/404.html` es una página 404 real (noindex), sin la redirección de GitHub Pages.
- Una página por agente (`/agentes/<slug>`, 33): salen de `src/data/agents.ts` vía `src/data/agentPages.ts` (título, descripción, preguntas y respuestas); los scripts de build las leen con `scripts/lib/seo-pages.mjs` (esbuild). Si cambia el catálogo, cambian solas: el prerender, el sitemap y la validación las incluyen.
- `node scripts/indexnow.mjs` avisa a Bing y otros buscadores (IndexNow) de las URL del sitemap tras un despliegue; la llave es el archivo `public/<32 hex>.txt`. `lastmod` del sitemap sale del último commit de los archivos de cada página (git o la API pública de GitHub; si no responde, se omite).
- Rendimiento: Google Translate solo se descarga si existe la cookie `googtrans` (el selector guarda la cookie y recarga); Google Analytics y el píxel de Meta solo se descargan si la persona aceptó el banner de cookies (y entonces, tras `load`); las fuentes de Google van con `preload`. Imágenes de las vistas previas en WebP; no subir imágenes de varios MB a `public/`.
- Píxel de Meta ("AI4U Pixel", ID público `2098400163896719`, el mismo que usan los anuncios): **solo carga si la persona aceptó el banner de cookies** (Ley 1581: autorización previa): `index.html` no descarga Analytics ni el píxel; la única puerta es `window.__ai4uLoadTrackers`, que llama `src/utils/consent.ts` al aceptar (o `index.html` si ya había aceptado en una visita anterior), y **nunca** con `navigator.webdriver` (el prerender del build no debe mandar visitas falsas ni pintar el banner). Antes de aceptar, `gtag` y `fbq` existen pero descartan todo. El banner es `CookieBanner` (aceptar y rechazar pesan igual; "Preferencias de cookies" en el pie lo reabre); retirar la aceptación borra `_ga*`/`_fbp`/`_fbc` y recarga. Los textos legales (`PrivacyPolicy`, `CookiePolicy`, `DataDeletion`) toman los datos del responsable de `src/data/legalEntity.ts`; mientras tenga valores "PENDIENTE" la política no los muestra y `legalEntity.test.ts` falla a propósito. Los eventos los dispara React: `MetaPixelTracker` (PageView por ruta + `Contact` al tocar enlaces `wa.me`) y `analytics.trackConsultationRequest` (botones que abren WhatsApp por código). La CSP vive en **dos** lugares y el navegador aplica la más estricta de las dos: el `<meta>` de `index.html` y la cabecera de `vercel.json`; cualquier dominio nuevo (Meta, Google, etc.) va en ambas (`src/utils/__tests__/metaPixelCsp.test.ts` lo vigila). Cualquier script de rastreo nuevo debe cargarse desde `__ai4uLoadTrackers`, nunca con una etiqueta `<script src>` suelta (`consent.test.ts` lo vigila).
- Mobile first: sin scroll horizontal a 375px; imágenes con `max-width: 100%`. Hay guía de optimización de imágenes en `docs/IMAGE_OPTIMIZATION_GUIDE.md`.
- **Accesibilidad (WCAG 2.2 AA + Res. MinTIC 1519/2020):** el diseño por defecto no cambia; las herramientas son opcionales. `scripts/prerender.mjs` corre **axe-core** (WCAG 2.0/2.1/2.2 A y AA) sobre cada ruta del registro en la misma pasada del prerender y **cualquier violación tumba el build**. Hay enlace «Saltar al contenido» (`Layout`, destino `main#contenido`), el botón flotante de WhatsApp vive en un `aside`, los encabezados no saltan niveles (tarjetas con `h2`, no `h3`, bajo el `h1`) y los iconos dentro de controles con nombre llevan `aria-hidden`. El panel «Accesibilidad» (`organisms/AccesibilidadPanel.tsx`, un solo `<dialog>` nativo montado en `Layout`; `AccesibilidadBoton` en cabecera y pie lo abre por evento) guarda preferencias en `localStorage` (`ai4u-a11y`, sin cookies ni terceros) y las aplica como atributos `data-a11y-*` en `<html>` (`utils/accesibilidad.ts`; `index.html` las aplica antes de pintar); el CSS de cada opción está en `styles/accesibilidad.css` (tamaño de texto con `zoom` en `body`, contraste alto, espaciado WCAG 1.4.12, fuente simple, sin movimiento). «Leer en voz alta» usa `SpeechSynthesis` del navegador (voz es-CO si existe) y una barra fija con pausar/detener. La declaración está en `/accesibilidad` (`pages/Accesibilidad.tsx`): actualizar la fecha de auditoría y las limitaciones cuando cambie algo. Reglas para contenido nuevo: ningún video sin subtítulos, ningún PDF sin etiquetar (mejor HTML), texto alternativo útil, 44 px táctiles, nada solo por color o solo por hover.
- No es multitenant ni toca SAP ni Supabase. No hay páginas de propuestas ni pitches (se eliminaron el 1-oct-2026 por ser contenido público con datos de clientes): no añadir cifras, precios, nombres ni datos confidenciales de clientes.
